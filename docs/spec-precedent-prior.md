## 0. 一句话

主线 `auto_challenge` 吃你过去的 kill 判例，让提问攻在你历史上真正死过的地方；`auto_verdict` **永不吃**——取证可自动化，定见不可。

## 1. 为什么是这一刀（诊断推翻了原提案）

原诊断是「L3 到 L4 中间没有 milestone」。查证结果是**L3 的主干道从来没接通**：

- `build_challenge_prompt(claim, context, evidence)`（`prompts.py:152`）参数里没有判例
- `build_verdict_prompt(claim, question, answer, evidence)`（`prompts.py:550`）同样没有
- `context` 是调用方传的自由文本（`routes.py:104,323`），不是历史投影
- 判例注入只活在 `build_contradiction_prompt`（②矛盾扫描）与 `build_taste_prompt`（①品味锚）

即：**Lens 读出只挂在两个特设入口——「起手扫矛盾」和「显式点评品味」。产品里跑得最勤的那条路完全不认识你。** 死因分诊四元组躺在事件流里，主线提问一条都没看。

不是中间缺台阶，是这一格没踩实。

### P2.5 准入线（本刀据此选中，M1-M4 据此出局）

grill 增强轴，两条硬线：

1. **对下一次拷问有可观测影响**（观察性仪表不算——你看完了系统什么都没变）
2. **冷启动不空转**（没料时可以沉默，但不许「要攒够 N 条才有用」）

判例先验四条全过：直接改提问角度 ✓ / **n=1 就生效** ✓ / 零新存储（复用 `verdict_precedent` 投影）✓ / 个位数判例的真实库里今天就有用 ✓。

## 2. 已决定（grill 钉死，不再翻案）

### Q1 — 分工：角度层，不是内容层

| | ②跨想法矛盾检测 | 判例先验（本刀） |
|---|---|---|
| 层 | 内容层 | 角度层 |
| 产出 | 多长一张 challenge 卡 | 同一张卡问得更像你 |
| 触发 | 撞上 ¬X / 重复 | 每次 auto_challenge |
| 例 | 「你旧 claim 断言 ¬X」 | 「你同类 claim 死于 boundary 三次 → 先攻边界，别先攻方法学」 |

### Q2 — 取证/定见不对称（铁律，不是实现偷懒）

- `auto_challenge` **吃**判例 —— 问得更准 = 取证，可自动化。
- `auto_verdict` **永不吃**判例 —— 判得「更像你以前」= 定见，越界。
- 防的是**前科定罪**：LLM 因「你以前 kill 过同类」而倾向 kill 当前 claim = 制造一致性而非求真，Lens 从反射品味退化成锚定惯性。verdict 侧不吃判例是它的结构防线，不靠 prompt 自觉。
- 附带结论：旧挂账「auto_verdict 容错不对称为什么反而对」——**因为两侧铁律地位不同**，不对称是设计，不是缺陷。

### Q3 — 注入形状

**选取：现在全量，轴钉死在 spec 里。**

- 注入范围 = Library 内全部 kill 判例（作用域照 glossary：Library 内穿透、跨库硬墙）。
- **确定性预算 = ts 倒序最近 12 条**；单条 rationale 复用现成 300 字截断（`prompts.py:24`）。
- **不建选取机制**——个位数判例的库不需要，那是给不存在的库建的。
- 但**轴现在就钉死**：将来判例数超预算要做选取时，轴 = `death_cause` + 攻击面（`target_aspect`）相似度，**禁止用主题词面粗筛**。
  - 理由：`prefilter_candidates` 零重叠即丢弃（`prefilter.py:43`）。而判例先验最值钱的恰恰是跨主题的——肿瘤影像死于样本量、电子病历也死于样本量，那是方法学惯性，词面重叠为零。用主题粗筛 = 只拿到同主题判例 = 那些已被②当矛盾卡处理过 = **本刀退化成②的影子，白做**。
  - 旁证：走查小尾巴「品味锚对词面重叠弱的 claim 沉默」，根同此处。
- 触发条件写明：**判例数 > 12 时**再议选取/压缩（= 原 M4 判例蒸馏的真实触发条件）。

**内容：注入原始四元组，不注入统计聚合。**

- 塞具体判例（`outcome + death_cause + rationale截断 + revival_condition`，复用 `format_precedent_lines`）。
- **不塞**「你 62% 的 kill 是品味死」这类分布：统计是对研究者本人的人格概括，回溯不到具体出处（取证形状要求可溯源），且属观察性物种——要进主线得单独拍，不许夹带。

### Q4 — 只吃 kill 判例，survive 判例排除

- kill 判例带死因分诊，先验价值明确：往哪攻。
- survive 判例的先验只有一个作用方向——告诉 LLM「这类 claim 他扛住过」——而这个方向的唯一效果是**软化拷问**。
- 命名：**前功赦免**（前科定罪的对偶）。两者都是把历史事实偷换成当下结论，方向相反。
- 前功赦免更危险，因为它撞 glossary 明令：**survived ≠ 正确性证书**。把 survive 判例喂进提问器，等于让提问器本身把「扛过一轮」读成「这类想法没问题」——比 UI 文案渲染错更深一层，侵蚀的是对抗性本身（架构原则第一条）。
- 被放弃的正当用途：「避免重复提问」。它**不需要判例**——用当前 artifact 已有的 challenge 列表就够，属 grill 本体的信息增益，与 Lens 无关。**挂账，不并入本刀**（并入会稀释验收线）。

### Q5 — 输出可观测（`precedent_refs`）

- CHALLENGE 事件 payload 带 `precedent_refs: [claim_id]` —— 这一问引用了哪几条判例。
- **幻觉过滤**：LLM 报的 claim_id 不在注入集合内 → 丢弃（同 `lens_service.py:290` / `:395` 的既有手法）。
- **不设「无判例不出问题」闸**——与①品味锚**不同**。品味锚无锚即沉默（无锚的品味判断 = 彩虹屁）；但主线拷问不能因为你没历史就罢工。**冷启动 = 逐字退化成今天的行为，不是沉默。**
- 前端徽章：复用 lens 卡「⟲ 来自你的轨迹」形态，标注这一问攻的是哪条判例，可点回溯源。
- 为什么这不是实现细节：不带 `precedent_refs`，本刀就是**黑箱改良**——问题变了但无人（含 canary）能断言是判例导致的，彩虹屁最容易藏在这种形态里；且**护城河不可见**，「判例被引次数 = Lens revealed utility」这个数**底下压根没埋**。

### Q6 — P2.5 = 本刀一把（M1-M4 处置）

| 提案 | 处置 | 理由 |
|---|---|---|
| M4 判例蒸馏 | **降级为本刀 v2** | 就是「注入预算超限后的压缩策略」。触发条件从「攒够 20-50 条」这种拍脑袋数字，变成 §Q3 的结构性事件（判例数 > 12） |
| M1 轨迹资产面板 | **等底数** | Q5 埋了 `precedent_refs`，判例被引次数从此是硬数；但本刀未跑前该数恒为 0，现在做 = 给空数据建仪表 |
| M2 复活监测 | **推 L4 前哨** | 不改变下一次 grill（准入线①不过）；它改变「你该重开哪条」= 议程层 = L4 物种。且个位数库里 circumstantial kill 约 0-2 条，无可监测 |
| M3 轨迹复盘 | **出局** | 观察性 + 要量，两条准入线都不过 |

## 4. 验收要点（就绪闸，非正确性证书）

**单测层**

1. 库有 kill 判例 → `auto_challenge` 的 prompt 含判例四元组（断言注入内容 + 300 字截断）。
2. survive 判例**不进** prompt（断言排除）。
3. `auto_verdict` 的 prompt **不含**任何判例——**回归断言**，防后人「顺手也接上」。
4. 空库 / 无 kill 判例 → prompt **逐字等于今天的输出**（冷启动不沉默、不空转）。
5. `precedent_refs` 幻觉过滤：LLM 报注入集合外的 claim_id → 丢弃。
6. 预算：判例 > 12 条时按 ts 倒序取最近 12（确定性，可断言）。

**live 层（真 DeepSeek，本刀区别于②的唯一证据）**

7. **跨主题命中**：种两条词面零重叠、死因相同（如同为 `refuted`/样本量）的判例 + 一条新 claim → 生成的问题攻在该死因上，且 `precedent_refs` 命中**跨主题**判例。这条不过 = 本刀退化成②的影子。
8. **对照**：无判例的空库跑同一条 claim → 不出现任何判例引用（不幻觉出处）。

**集成层**

9. 前端徽章渲染 + 可点回溯源。
10. 全测试套件过；**prompt 变了 → L3 canary 必跑**（触发纪律第一条）。
