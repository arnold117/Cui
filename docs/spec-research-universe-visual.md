## 1. 视觉命题

Cui 是一张会被长期使用、不断留下研究痕迹的**矿物研究桌**。

它不是无菌 SaaS dashboard、文献库存、无限画布或暗色 AI 控制台。用户应感觉：自己可以长时间阅读、写作、比较材料和回看来路；而当内容被确认时，界面留下克制、可追溯的“淬”痕，而不是用效率分数或彩色徽章奖励行为。

### 1.1 气质分工

- **研究桌为基底**：稳定、安静、可长时停留。
- **锻／淬为 signature**：仅通过状态边缘和确认瞬间的冷青绿出现；绝不做火焰、铁砧、金属拟物或赛博熔炉。
- **严厉但耐心**：待回应张力清楚但不带错误惩罚感；Cui 的表面不喧闹、不催办。

## 2. Token 系统

### 2.1 色彩

| 名称 | 值 | 用途 |
|---|---:|---|
| 矿物底 `stone` | `#EAEBE7` | 全局研究桌背景 |
| 阅读面 `paper` | `#F8F8F4` | 探索稿、材料、方向／PARK 主工作面 |
| 深石墨 `ink` | `#222725` | 主正文、坚定操作、深色行动面 |
| 雾灰 `muted` | `#68716E` | 元数据、来路、低优先级辅助文字 |
| 细线 `line` | `#D6D9D3` | 结构边界、分隔，不制造卡片墙 |
| 确认边缘 `edge` | `#315B51` | 已确认结构的稳定边缘／文字 |
| 淬色 `teal` | `#2D8C84` | **只用于用户确认瞬间**与确认痕迹 |
| 待回应 `rust` | `#A94B39` | 未确认反证、待回应研究张力；不是通用 error 红 |

### 2.2 色彩规则

1. 默认界面应主要由矿物底、阅读面、深石墨和细线构成。
2. `teal` 不作为普通主按钮色或装饰色；它只标记用户确认、已落位的取证／结晶，或确认动作的短暂状态转变。
3. `rust` 只表示尚待研究者解释的张力；不能等同于“错误”“失败”“被否定”。
4. 未定探索不靠鲜艳色彩标记；使用低密度文本、灰色来路与保留空间表达。
5. 不使用渐变作为装饰。允许在用户主动选中的探索片段后，使用从极淡淬色到透明的局部背景，表达“已被用户指出、但尚未确认”。

## 3. Typography：双层阅读

视觉上必须先让人区分“正在与研究内容相处”与“正在操纵研究结构”。

| 层 | 英文 | 中文 | 用途 |
|---|---|---|---|
| Reading face | Charis SIL | Source Han Serif | 探索稿、材料摘录、方向命题、用户结论、答辩内容 |
| Working face | IBM Plex Sans | Source Han Sans | 导航、问题脊柱、claim／证据结构、状态、操作、元数据 |
| Utility face | 暂不另设 | 暂不另设 | 首期复用 Working face；不得为装饰加入等宽字体 |

### 3.1 排印规则

- Reading face 是内容的阅读节奏，不得被拿去制作夸张品牌大标题。
- Working face 负责界面秩序；避免系统默认 sans 或典型 SaaS 字体成为无意识 fallback。
- 阅读正文优先保证长时舒适：控制行长、较大行距、低反射背景；不为“信息密度”压缩探索稿与材料摘录。
- 中英文必须共同测试字号、行距、标点与字重，不可只按拉丁字体验收。

## 4. 空间系统

### 4.1 全局

- 顶栏轻且稳定：Cui 标识、研究路径、捕获、开始。
- 禁止对象型主侧栏（方向／工作区／PARK／DOC 作为平行文件夹）。
- 研究路径提供位置感；它不是项目树。

### 4.2 两种密度

| 模式 | 目标 | 页面 |
|---|---|---|
| **读／想** | 保持连续思考与材料精读 | A 阅读桌、B 证据台、D 工作区／锻 |
| **扫／盘点** | 快速辨认方向结构、结晶与张力位置 | C 方向地形、研究边缘 |

两种密度共享色彩、字体和边缘语法；不能做成不同产品主题。

### 4.3 主工作面 + 研究边缘

工作区由一块主工作面与克制的研究边缘组成：

- 主面用于自由探索、局部 Grill、材料对照或结晶；
- 研究边缘只露出 1–2 个有语义的对象摘要，待回应优先于计数；
- 不显示完成率、健康度、产出统计或“下一步”；
- 窄屏时研究边缘变为底部抽屉，不能压缩阅读面。

## 5. 已验证的页面语法

### A — 阅读桌：问题工作区

**已验证**：连续 serif 探索稿 + 轻量问题脊柱 + sans 研究边缘，可作为长期阅读／写作的主面。

- 用户主动选择的片段使用极淡淬色底与左侧边缘；这表示“被指出”，不表示已确认。
- 锻、审查地形和裁决使用工作区内的**右侧聚焦面**，原探索稿仍保持可见。
- 禁止用居中 modal 替代锻／审查／裁决；它会把研究桌降格为 SaaS 表单。

### B — 证据摊开：材料—claim 对照

**已验证**：材料摘录与 claim／候选判断并列；用户确认后在原地改变认识论地位。

- 材料、claim、Cui 的未确认候选必须同台；禁止只显示“反驳／支持”标签。
- 确认后只出现局部“事实已落位”回执及淬色，不能自动跳转、自动 verdict 或用 modal 中断比较。
- 证据锚、来源定位与不确定性应当比“模型结论”更稳定可读。

### C — 方向地形：研究宇宙入口

**已验证**：方向命题优先于计数和任务；局部放大的方向视口保留研究宇宙上下文。

- 默认是命题化的方向地形，不是 force graph、任务卡墙或项目列表。
- 选中方向后，在原地扩大为**方向视口**：其他方向退到背景但不消失；选中方向显示问题试验、结晶和待回应事实。
- 方向视口不等于详情管理页。禁止在此加入方向命题编辑、完整工作区管理、活动流或表单墙。

### D — 密封到形成：PARK → 放行 → 工作区 → 锻

**已验证**：PARK 与工作区应使用同一张研究桌的空间／排印系统；密封靠语义与细微边缘，而不是换一套“档案室”视觉。

- PARK 是同一工作面上的未承诺便条，靠 `◇`、低对比度边缘和“Cui 不会读取”的清晰文案表达密封。
- 放行台也是同一工作面中的局部状态，不是多步 wizard，也不是文件移动界面。
- 放行后问题试验场直接继承 A 的问题脊柱与探索稿。
- 锻直接继承 A 的右侧聚焦面；PARK 原件以细小、可回溯的放行来路存在，不能抢走当前探索。

## 6. 明确拒绝的视觉／交互形态

以下已在原型中被验证为错误方向，生产实现不得重新引入：

1. **全局通用 modal**承载锻、审查、取证、结晶或方向更新：破坏页面阅读层级，变成通用 SaaS 表单。
2. **PARK 独立档案室**：大侧栏、厚卡片、沉重封闭的视觉，会让 PARK 与研究宇宙成为两套产品。
3. **方向详情管理页**直接替代地形：把方向变成项目目录，吞掉 C 的留白与地形感。
4. **默认 graph-first**：图是未来一种关系投影，不是日常研究的第一阅读面。
5. **暖奶油纸 + 陶土色的默认 AI 美学**，以及深黑酸性高亮的 AI 控制台美学。
6. **卡片墙／状态 badge 墙**：结构边界必须服务研究对象和认识论地位，不能成为装饰。
7. **产量、完成率、连续使用、优先级或健康分**作为视觉主叙事。

## 7. 动效与状态转变

- 常态以静止、低干扰为主；不得用持续动画制造“AI 正在工作”的焦虑感。
- 唯一显著动效是确认瞬间的**淬色**：冷青绿在局部边缘／小圆点短暂出现，随后沉为稳定 `edge` 状态。
- 待回应事实不闪烁、不红点轰炸；其可见性来自它所在的研究结构。
- 尊重 `prefers-reduced-motion`；动效不得承载唯一信息。

## 8. 原型验证状态

| 路径 | 状态 |

| A：探索 → 锻 → 审查 → 裁决 | 已验证视觉与局部交互 |
| B：取证候选 → 用户确认 → 事实落位 | 已验证视觉与局部交互 |
| C：方向地形 → 原地方向视口 | 已验证视觉与局部交互 |
| D：PARK → 放行 → 工作区 → 锻 | 已验证视觉与局部交互 |
| 完整旅程：PARK → 放行 → claim → 审查 → 裁决 → 取证 → 研究宇宙 | 已验证原型状态连续性与引导；仍须在生产数据模型上复验 |

## 9. 生产落地前的视觉验收

- 同一用户在 A/B/C/D 间移动时，必须感到是在同一张研究桌上工作；
- 长文探索与材料摘录在典型笔记本屏幕上可连续阅读，不被卡片／标签噪音打断；
- 用户无需依赖颜色，也能区分未定探索、Cui 候选、已确认取证与用户结论；
- 所有确认动作都留下可见但不喧闹的淬色痕迹；
- PARK 的“Cui 不会读取”边界在第一眼可理解，且放行后原件来路可回看；
- 不出现本章已拒绝的形态。

## 10. 完整旅程验证结论

原型以同一份内存状态走通：**密封 PARK 捕获 → 用户放行 → 问题试验场 → 用户形成并提交 claim → 审查／答辩 → 用户裁决 → 材料取证候选 → 用户确认反证 → 回看研究宇宙**。

验证结论：

1. 用户需要情境化的原型引导，才能理解此时可做的动作及其为什么存在；抽象步骤条或跨页跳转不能替代真实上下文。
2. 每一步产生的对象必须真实成为下一步的可见来路；使用各页预填假数据会使“研究宇宙”失去因果连续性。
3. 用户确认的材料反证可以进入方向回看，但不得自动推翻 claim 或替用户改变 verdict。
4. PARK 原件、放行引用、claim、审查轮次、确认取证在最终回看中均应保持可追溯；最终页面的职责是显示研究位置，而不是显示旅程完成度。
5. 原型引导仅服务于验证，**不是正式产品中的线性教程或研究流程强制器**。

生产实现必须在真实事件与投影模型上重新验证这条路径，不能将此原型内存状态机直接提升为产品代码。
