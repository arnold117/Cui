# Spec：最小研究宇宙（Phase 1）

> 状态：已收敛（2026-08-03 产品形态 grill）。
> 
> 父文档：[`prd-research-universe.md`](prd-research-universe.md)。本文只定义**现在必须交付的最小闭环**，并明确本期不做什么；不替未来阶段预先写实现细节。

---

## 0. 一句话

用户从一个未承诺捕获或开放问题出发，在问题试验场中探索、形成并检验多个 claim、确认最小真实取证与探索结论，再由用户决定其如何改变一条长期方向；之后 Cui 在该结构中呈现仍待回应的事实。

```text
PARK 原始捕获（可选、密封）
  → 用户放行到问题工作区
  → 自由探索 / 手动带入材料
  → 用户形成多个 claim 并独立 Grill
  → Cui 提出挑战、带依据的取证候选
  → 用户确认 verdict、取证与工作区结论
  → 用户确认对方向命题的影响
  → 方向阅读面在实际位置呈现待回应事实
```

## 1. 本期要验证什么

这不是在旧 Grill 外加一个 dashboard。必须验证的新产品语法是：

1. 用户可围绕**问题**（不是预先存在的 claim、文稿或项目）开始工作；
2. 工作区可容纳自由探索、材料与并行、独立可追责的 claim 审查；
3. 一个问题能以 survived claim 之外的方式正当地结晶；
4. 结晶可由用户塑造其长期方向，而非系统自动总结；
5. 下次进入时，用户面对的是嵌入方向／工作区的事实，而非任务列表或全局评分。

## 2. 本期领域对象与硬边界

### 2.1 PARK Capture

- 用户可零摩擦创建原始捕获。
- 默认密封：Cui 不读、不搜、不总结、不关联、不挑战，不进入 Lens 或任何默认入口。
- 用户可主动放行到新／已有工作区，选择暂定角色：触发问题、探索内容、待取证材料线索，或暂不命名。
- 放行在工作区中创建**带来源引用**；PARK 原件不移动、不改写。
- 放行内容默认先作为未定探索／材料线索；若用户要形成 claim，默认进入 GRILL 的低强度**锻**阶段：Cui 只问澄清问题，可展示通用静态模板，但不生成候选 claim、定制骨架或具体研究路径。用户自己写下并确认新 claim 后，记录与 PARK 原件的 `forged_into` 谱系；原件永不被改写。用户可一键跳过锻，直接提交已成形的自写 claim。
- 本期不做 PARK 的 AI 找回、范围搜索或复杂整理。

### 2.2 Workspace（问题试验场）

- 创建时必须由用户写下开放问题；不能要求先有 claim。
- 工作区问题可由用户重述、收窄、扩展、拆分或转向；每次实质变化保留原问题、变化类型与理由。
- 用户显式位置：`exploring`、`paused`、`concluded`、`absorbed / branched`。系统不根据活动、claim 状态或时间自动改变。
- `concluded` 必须有用户确认的探索结论，允许极短；它可为回答、否定路径、边界、关键未知、暂缓条件或转向。用户可明确**重开**已 concluded 的工作区，记录重开的理由；新的结论是新的位置更新，旧结论及其当时依据永远保留，不能编辑替换。
- 本期支持自由探索笔记。笔记默认未确认，不是 claim、证据、结论或 Lens 输入；用户可选择片段作为当前 Grill 的未确认上下文，Cui 不得将其升格为立场或证据。

### 2.3 Claim 与审查轮次

- 用户自写文本后，可明确提交为 claim；Cui 可基于形式提示“这里已有断言、范围与潜在反例”，但不能改写／生成候选 claim 或自动提交。
- 同一工作区可并行存在多条 claim；每条 claim 有独立、身份可追溯的**审查轮次**。一轮次绑定：发起它的工作区与问题版本、被审 claim 的不可变文本快照、该轮 challenge／答辩／材料关系候选，以及该轮最终 verdict 或明确撤回。`answer` 不会自动解决 challenge；只有该轮的用户确认 verdict、用户撤回 challenge，或将其明确暂缓，才改变“待回应”状态。
- 已有 verdict 的 claim 被新材料或新语境重审时，必须创建新审查轮次；旧轮次和 verdict 保留为当时结果，不能被新轮次覆盖。
- Claim 记录发源工作区，为未来跨工作区引用留出身份锚点；本期无需实现完整跨工作区重审 UI。
- 每次 challenge、答辩、verdict 与材料—claim关系都绑定到其审查轮次及该轮 claim 文本快照。纯表达澄清可创建新的可见文本版本，但不改变已存在快照；由用户判断是否仍属澄清。实质修改（断言、范围、关键概念、机制、可反驳条件）必须产生新 claim、关联其前驱，并由用户确认收窄、修正、替代等谱系关系；本期可后置完整谱系 UI，但不得省略不可变前驱关系。

### 2.4 最小但有立场的 Grill

- 对已提交 claim，Cui 提出带明确攻击面的 challenge；不能退化为泛泛“请补充细节”。
- 每个 challenge 应说明为何该攻击面重要；本期“教学”限于当前 challenge 的方法说明与通用自检方法，不建立独立导师对话、历史学习或任何具体研究内容生成。
- Claim 支持多个待回应 challenge、用户答辩与人工确认的 verdict。
- Kill verdict 必须记录用户确认的理由，并至少区分：`refuted`、`not_worth`、`boundary`、`circumstantial`；`circumstantial` 必须有 revival condition。
- 本期不要求跨工作区矛盾检测、判例先验、品味锚、自动方向候选或任何需要历史积累的 Lens read-out。既有日常 Grill 的自动 read-out 若被迁入，仍必须遵循其既定边界：判例先验只改变 `auto_challenge` 的攻击角度、引用可追溯的 kill 判例、永不进入 auto-verdict；本期不以新增该能力为验收目标。

### 2.5 最小真实取证

- 用户可向工作区手动带入一份材料或摘录。
- 材料进入时仅是待取证对象，不能自动构成方向事实或支持某主张。
- Cui 可针对已有 claim 提出 `supports` / `contradicts` / `silent` 候选；候选必须展示不可变的材料证据锚（原始摘录快照 + 来源定位／最小元数据）、其针对的 claim 文本快照与不确定性。
- 用户确认、修正或拒绝后，关系才成为已确认取证事实；确认／修正后的关系保留同一证据锚，不能只指向可编辑 Material 记录。
- 解析失败、证据不足或无法判断必须显式呈现，永不伪装为 `silent`。
- 用户拒绝应是低摩擦；可选理由包括不涉及、证据不足、误读、应关联另一 claim、或 claim 需要重审。
- 本期不做自动外部搜索、PDF 大规模解析、引用链追索、材料推荐、跨库材料图或自动综述。

### 2.6 Direction（长期研究命题）

- 用户可直接创建方向命题，或从工作区开始后再创建／关联方向；创建顺序不决定正统性。
- 方向命题回答长期意图，不是待证 claim。
- 工作区可显式关联零、一或多条方向；本期至少支持关联一条，数据模型必须不阻断多对多。关联、解除关联与重关联都是可回放的用户事件：解除只结束当前归属，不抹去曾经关联过的事实。
- 用户声明方向状态：`active`、`watching`、`retired`；系统只展示事实，不自动改状态。
- 工作区 concluded 后，Cui 展示它所关联方向及局部事实；用户明确选择：只留为局部结晶、作为方向结晶，或重述方向命题并说明理由。由结论触发的方向重述必须同时记录工作区结论引用与用户理由；直接创建方向不伪造此来源。
- 本期不做自动方向候选、方向间关系、工作区间关系、分叉／合流 UI 或影响范围计算。

### 2.7 最小方向阅读面（默认入口）

方向阅读面不是空间网络图，也不是任务 inbox。它至少显示：

- 方向命题、用户声明状态、关联工作区与最近已确认结晶；
- 该方向／工作区中的待回应事实：未决 claim challenge、待确认材料关系、用户暂缓事项；
- 未归属工作区。

待回应事实必须在其影响的方向／工作区中出现，而非按对象类型平铺或由系统给出全局优先级。Phase 1 的最小生命周期如下：

- **challenge**：创建后为 `pending`；answer 只记录答辩，仍为 `pending`；同一审查轮次的用户确认 verdict、用户明确撤回，或用户暂缓（写下重看条件／理由）才使其退出默认显著层。暂缓的 challenge 保留为可回看的挂起事实，不能因已读消失。
- **材料关系候选**：创建后为 `pending`；用户确认、修正、拒绝或明确撤回后退出默认显著层。拒绝不进入已确认事实，但保留可选理由；之后只能经新的候选／新的取证轮次重开，不能改写旧决定。
- **暂缓事项**：只能由用户显式创建，或由上述对象的暂缓动作产生；它保持在所属工作区的挂起层，直到用户重开、吸收或撤回。
- **关联／吸收**在本期仅指：用户将一个 pending challenge 或候选关联到一个明确工作区／审查轮次，使它在该处继续以 pending／挂起事实出现；不创建复杂工作区关系，也不将它视为已确认结论。

不可仅靠“已读”划掉任何事实。

本期不做方向间／跨方向张力、复杂关系、候选影响分层、空间图、结构变化史或全局优先级排序。

## 3. 用户旅程与验收场景

### 场景 A：从 PARK 开始

1. 用户捕获“X 与 Y 好像有关系”；Cui 不自动分析。
2. 用户选择以它触发新问题，写下“在何种条件下 X 与 Y 存在可解释关系？”
3. 工作区保留 PARK 原件的放行引用，原件仍可在 PARK 原样查看。
4. 用户写探索笔记；在自写文本中形成一个 claim，明确提交 Grill。
5. Cui 提出有攻击面、能解释其方法意义的 challenge；用户答辩并确认一个 verdict。

**验收：** 未放行 PARK 内容不可进入任何系统上下文；放行后不篡改原件；claim 由用户提交，非 Cui 生成。

### 场景 B：最小材料取证

1. 用户将一段论文摘录带入工作区。
2. Cui 将其作为待取证材料，并对某条现有 claim 提出带出处的 `contradicts` 候选。
3. 用户拒绝，说明“涉及相邻对象，不涉及此 claim”。
4. 该关系不进入已确认事实层；拒绝理由可回看。
5. 用户对另一候选确认 `silent`；它作为“查无”被保存，但不伪装成反证或支持。

**验收：** 系统取证候选与已确认关系清晰分层；没有用户确认不得沉淀；失败不被伪装成 `silent`。

### 场景 C：问题结晶并影响方向

1. 用户在一个工作区并行检验两条 claim：一条 `boundary` kill，一条暂时 survived。
2. 用户将工作区 concluded，并写下结论：“原问题在 A 范围外无法成立；后续应检验 B。”
3. Cui 显示该结论与方向命题的关系；用户选择重述方向命题，记录理由。
4. 默认方向阅读面显示新命题、该工作区结晶，以及尚未回应的另一条材料关系候选。

**验收：** survived claim 不是工作区唯一合法产出；方向不会被系统自动改写；待回应事实嵌入其真实上下文。

## 4. 明确不做（本期负清单）

- 自动外部检索、PDF／引用链基础设施、大规模材料图；
- 跨工作区矛盾扫描、判例先验、品味锚、自动方向候选、L4 议程扫描；
- 工作区／方向复杂关系、影响范围、空间网络图、结构变化史；
- 完整 DOC 成形面与 DOC 缺口回流；
- 协作视窗、外部视角模板；
- 研究取舍原则、历史教学观察、独立课程／能力地图；
- 跨时间提醒与订阅；
- 用活动量、完成率、优先级分数或“健康度”定义研究进展；
- 为用户生成具体 research claim、机制、路线或自动 verdict。

## 5. 架构约束

1. **原生重建。** Workspace 成为日常研究活动中心；Direction 是长期命题；Claim 是可跨语境的节点；DOC 后续成为独立成形面。不得将 Workspace 做成旧 Artifact 的薄包装或形成两套长期并行的用户模型。
2. **事件与谱系。** 高阶判断、问题演化、verdict、取证确认、结论与方向影响必须可回放，不允许无痕覆盖。具体字段与事件命名由实现阶段 test-driven 决定。
3. **确认闸门。** 只有用户确认的判断、关系和结论可进入已确认研究宇宙；未确认笔记、PARK 内容与系统候选必须有独立认识论地位。
4. **可追溯性。** 已确认取证须回到材料依据；方向变化须回到工作区结论；PARK 放行须回到原件；Cui 产生的候选须能展开其基础。
5. **全新宇宙切换。** 新模型启用时创建新的、空的研究宇宙。既有 Artifact、Claim、Trajectory、Material 与 PARK 数据整体保留为只读 legacy archive：不自动翻译、不喂入新 Lens、不能与新 Workspace／Direction／Claim 混用。不得为保留旧语义将 Workspace retrofit 成 Artifact 包装，亦不得形成长期双中心模型。旧 archive 的导出／删除权按既有隐私规则另行处理。
6. **先验证模型，不预建未来。** 不为自动方向发现、GraphRAG、协作或复杂图谱先造空架构；仅保留不阻断本 spec 已决定多对多关系与可追溯性的最小扩展点。

## 6. 就绪闸

本期完成不以“页面数量”判断。至少必须能在真实应用中完整跑通场景 A、B、C，且：

- 所有用户确认闸门真实有效，不能仅靠前端文案；
- 任何由 Cui 参与的 prompt／取证改动都有真实模型 live 验证，不能只靠单测证明指令存在；
- PARK 密封、未确认内容隔离、材料三态与方向不自动更新都有回归测试；
- UI 能让用户明确分辨：我的判断、已确认取证事实、Cui 的待回应候选、未定探索；
- 不出现自动优先级、自动 verdict、自动方向归属或将 survived 渲染成真理证书。
