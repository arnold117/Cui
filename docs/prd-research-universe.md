# PRD：Cui 研究宇宙

> 状态：已收敛（2026-08-03）；由产品形态 grill（82 问）形成。
> 
> 本文定义 Cui 重设计后的**产品定位、完整能力地图与分期边界**。首期的具体行为与验收见 [`spec-research-universe-mvp.md`](spec-research-universe-mvp.md)。

---

## 1. 一句话定位

**Cui 让严肃研究者持续经营一个会反过来质询自己的研究宇宙。**

它不是检索工具、综述生成器、知识库、项目管理器或替人研究的副驾。它让问题、主张、材料、失败、转向与作品积累成私有、可追溯的结构；再以具体事实，将矛盾、缺口、惯性与未解张力带回研究者面前。

研究者始终拥有：研究问题、长期方向、证据意义、价值取舍与最终判断。Cui 自动化取证、保存来路、揭露结构、教授方法；**永不自动化定见**。

## 2. 用户与核心结果

### 首要用户

长期形成、检验并演化研究判断的人：硕博、博士后、青年教师及研究导向的专业人士。

他们共同面对可检验的主张、真实材料、方法边界、多条研究线与高代价判断。论文、proposal、review 等是重要产物，但不是产品中心。

### 情感承诺

主感受是：**逐渐拥有自己的研究地形。**

Cui 应让用户感觉到：问题、判断、死路和转向没有散掉；用户越来越看得懂自己在追什么、在哪里改变过。它具有“严厉但耐心、授人以渔的导师”气质：不放过跳跃与自欺，但教用户如何自己构造反例、比较解释、判断证据与拆开问题；绝不替用户决定研究路线或结论。

## 3. 不可违背的产品原则

1. **研究宇宙是第一性对象，文稿不是。** 文稿是从研究宇宙中成形、面向外部的独立产物。
2. **问题优先于 claim。** 工作区围绕开放问题；claim 是为推进问题而由用户自写、主动提交检验的工具。
3. **自动化取证，永不自动化定见。** 系统可检索、提取、找反例、提出挑战与揭露关系；人作出或确认 verdict、方向、价值和议程判断。
4. **演化不可无痕覆盖。** 问题、claim、结论、方向与关系可重开、分叉、收窄、合流或退役，但重大意义变化必须留下谱系和理由。
5. **Lens 只学习用户放行、经过闸门的轨迹。** PARK 与自由探索不会自动进入 Lens。系统候选也永不伪装为用户的判断。
6. **失败是资产。** 被证伪、不值得、需要收窄、暂缓待条件，是不同且可复用的研究结晶。
7. **沉默是硬能力。** Cui 在未承诺的形成、用户正在裁决、以及研究身份／意义解释上保持沉默，不抢写、不抢判、不替用户叙事。
8. **私有默认。** Lens 和研究宇宙默认私有；未来协作只能通过用户开启的对象级视窗发生。
9. **不以效率冒充研究进展。** 不做字数、连续天数、完成率或“健康分”；只呈现用户确认的研究位置变化。

## 4. 完整产品模型

### 4.1 研究宇宙与方向图

“方向图”是 Cui 的主关系模型和主视角，不承诺某一种图形组件。它的不同投影可以回答不同问题：方向地图、局部关系、结构变化史、张力视图，以及未来的议程扫描。

默认入口不是 inbox，也不排“下一步”。它把高资格的待回应事实嵌入实际影响的方向／工作区，回答：**我的研究宇宙哪一处有事实等待我解释？**

可进入默认入口的事实仅包括：

- 用户已承诺、尚未回应的取证（challenge、待确认关系）；
- 跨工作区／方向的已确认结构碰撞；
- 用户留下、现在可能相关的复活条件。

系统不因“问题漂移”、长期未动或活动量催办用户；不能替用户对研究排优先级。

### 4.2 方向

方向是用户拥有的、可演化的**长期研究命题**：回答“为什么这些试验共同构成我正在追的研究方向？”它不是待证 claim、项目计划或普通标签。

- 可直接由用户创建，也可由工作区自然长出；系统只可提出带证据的方向候选。
- 工作区可属于零、一或多条方向；每条归属由用户确认。
- 用户声明 `active`、`watching`、`retired`；系统只能显示活动、未决事实等旁证，不能自动判死活。
- 命题可重述；重大变化以分叉、合流、退役等谱系事件保留。
- 未来方向间可有少量、用户确认且可回溯的关系：`supports`、`tensions-with`、`shares-question`。

### 4.3 工作区

工作区是围绕一个**开放问题**的试验场，回答“这次我要弄清什么？”它可容纳笔记、材料、多个并行 claim、挑战、结论和后继问题；不是文件夹、论文项目或单一 claim 的容器。

问题可重述、收窄、扩展、拆分、转向，但须保留原问题与理由。工作区的用户位置是 `exploring`、`paused`、`concluded`、`absorbed / branched`；系统不能自动结案。`concluded` 必须有用户确认的探索结论，但可以极短。

工作区之间未来可有用户确认的关系：`builds-on`、`tests`、`competes-with`、`reframes`。

### 4.4 Claim 与 Grill

Claim 是用户愿意交给检验的最小断言。它有发源工作区，但不是其私有物：其他工作区可显式引用、以新材料重新审查它。

同一 claim 可有多次带语境的审查轮次；旧 verdict 保留为当时的结果，不是永恒真理。表达澄清可更新可见文本；改变断言、范围、概念、机制或可反驳条件时，必须产生新 claim，并由用户确认收窄、修正、替代等谱系关系。

Grill 是有攻击面、可解释、可答辩的挑战系统，而不是泛泛聊天或自动裁决器。Cui 可教用户为什么一种挑战重要、如何自己检验它，但不为用户生成其研究主张或替其作 verdict。

### 4.5 材料与取证

材料可由用户带入工作区，作为问题触发、异常、比较对象或待解释线索。它们不自动说明任何结论。

Cui 可以搜寻、解析、比较并提出材料—claim 关系候选：`supports`、`contradicts`、`silent`。候选必须给出原文／结果依据与不确定性；只有用户确认、修正或拒绝后才成为已确认取证事实。解析失败不得伪装为 `silent`。

未来材料发现应按潜在取证角色呈现（支持、反例、概念界定、方法路径、冲突或尚不明），而非黑箱相关度或自动综述结论。

### 4.6 PARK 与锻

PARK 是研究宇宙之外的、零摩擦且密封的未承诺捕获层。它不被 Cui 自动读取、检索、总结、关联、挑战或送入 Lens。

用户主动放行后，原件仍留在 PARK；工作区只获得带来源的放行引用。若用户要把未成形内容变成 claim，默认进入 GRILL 的低强度**锻**阶段：Cui 只问澄清问题、可展示所有问题通用的静态 claim 模板，但不提供候选 claim 或为该念头定制骨架；用户自己写下并确认一个新 claim 后，才跨形成闸。原 PARK 原件不改写；它与新 claim 的 `forged_into` 谱系必须可追溯。用户可一键跳过锻，直接提交已成形的自写 claim。未来用户可在明确选定范围内请求一次性找回 PARK，但系统解释仍只是候选，不能自动沉淀。

### 4.7 DOC

DOC 是研究宇宙的独立成形面。每份 DOC 由用户写下的外部沟通命题定义：面向谁、希望其理解／接受／行动什么、作品类型与约束。

Cui 可从用户选择的、**survived、已确认且无 verification debt** 的 claim 与其已确认、可追溯的取证中提出结构、暴露论证缺口、生成逐段可追溯并需确认的草稿。未决 claim、未确认关系、PARK、自由笔记和系统候选可以在 DOC 中作为明确标注的探索上下文，但绝不能充当外部论据。它不得用流畅表达掩盖论证断裂、将未审内容写成论据，或把生成文字回写为用户研究判断。DOC 暴露的研究缺口只能成为用户可吸收的候选，不能自动开新议程。

### 4.8 导师、Lens、协作与取舍原则

- **导师层**：用户可情境化追问“为什么这是问题”“如何自己检验”；Cui 教方法和思考操作，不代做具体研究内容。未来独立课程／能力地图另议。
- **Lens 有两类读出，必须分开。** （1）日常 Grill 的自动、取证型读出可在每次 `auto_challenge` 使用 Library 内已确认的 kill 判例，改变攻击角度；它必须可回溯到具体判例，且**永不进入 auto-verdict**。（2）用户主动盘点或开启“从历史学习”时，Lens 才可基于多个已确认案例提出非人格化、可拒绝的方法观察；不输出能力诊断或弱点分数。
- **研究取舍原则**：用户可显式写下、重开与退役价值承诺。相关时 Cui 可提出可忽略的自我张力，永不把它们变成规则或裁决。
- **协作**：默认私有。未来协作者可通过对象级视窗提交署名的 challenge、材料或建议；只有用户能吸收为自己的轨迹和 Lens。外部视角只能是用户写下的静态模板，不能模拟真人。

## 5. 分期路线图

### Phase 1 — 最小研究宇宙（本期，必须实现）

以“问题 → 试验 → 结晶 → 用户确认方向影响 → 宇宙以事实带回用户”为完整闭环。详见 [`spec-research-universe-mvp.md`](spec-research-universe-mvp.md)。

包括：最小 PARK—锻—claim 闸门、问题工作区、探索笔记、并行 claim／基础 Grill、手动带入材料与真实取证确认、方向命题与最小方向阅读面。

### Phase 2 — 结构与演化（当前后置）

前提：Phase 1 已有真实用户轨迹，工作区—方向的基本语义经使用验证。

候选能力：工作区／方向间关系、方向谱系、结构变化史、复杂的待回应事实、方向候选及其未采纳解释层、已确认与候选影响范围分层、PARK 一次性找回、自动外部检索与材料多入口。

### Phase 3 — 成形与反思（当前后置）

前提：有足够可追溯的结晶与来源关系，DOC 不会退化为无依据的生成器。

候选能力：独立 DOC 成形面、研究缺口回流、研究取舍原则、用户发起的方向／工作区盘点、情境化导师层、历史方法观察、有限的提醒。

### Phase 4 — 议程与协作（当前后置）

前提：多方向、多工作区、关系质量和用户信任足以避免空图／伪发现。

候选能力：对象级协作视窗、外部输入吸收、外部视角模板、L4 跨方向威胁扫描、复活条件监测，以及其所需的 Tier-1 持久、可审计的语义图。

**L4 的额外硬前提：** 在任何 LLM 产生的语义边参与 centrality／威胁排序前，必须单独决定：只允许用户确认的边计入，或结果明确披露使用了多少尚未确认边。不得将系统产生、可撤回的边称为“用户确认”。

**GraphRAG 属 Tier-2，仍是单独的架构决策，未承诺进入 Phase 4。**

## 6. 明确不做

无论在哪一期，Cui 都不做：

- 替用户形成其具体研究主张、机制、研究路线或价值判断；
- 自动 verdict、自动杀死／拯救 claim、自动改方向或排议程优先级；
- 用研究产量、连续使用、活跃度或健康分评价研究；
- 将 PARK、自由笔记、系统候选或协作者输入静默当作用户 Lens；
- 将系统聚类、相似度或未确认语义边伪装为研究事实；
- 共享整个 Library／Lens，或模拟真实导师／合作者的思想。
